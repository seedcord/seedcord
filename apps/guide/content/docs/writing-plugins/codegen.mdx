title: Writing types from codegen
description: Give your plugin's methods autocomplete and exact types for what it reads from the bot's project, like the names in its JSON files, using codegen().
---

Say your plugin sends saved replies, called tags. A bot keeps them in `tags/*.json`, a handler calls `tag('rules')`, and your plugin looks up `rules` in those files. You write the plugin before any bot exists, so its types can't list which tags a bot's files will hold. Without codegen, `tag()` takes any `string`. The bot's author doesn't get suggestions, and a typo like `tag('rulse')` is only caught when a user gets the wrong reply.

## How it works

You add a [`codegen()`](ref:core/Plugin.codegen) method and a `static readonly id` to your plugin. Three things then happen:

```txt output
1. your codegen() returns a value
   { replies: { welcome: true, rules: true } }

2. seedcord codegen writes it as a type into the bot's seedcord-gen.ts
   'seedcord-tags': { replies: { rules: true; welcome: true } }

3. your plugin reads it back with Generated<typeof Tags>['replies']
   { rules: true; welcome: true }
```

Shape the return value like the type you want. Each key of an object becomes a key of the type, an array becomes a tuple, and a string becomes its literal. `seedcord codegen` runs your `codegen()` in every bot that attaches your plugin, and `seedcord dev` runs it each time the bot starts. Each bot gets a type built from its own files.

```ts twoslash title="src/plugins/Tags.ts"
import { Plugin, readFiles } from '@seedcord/gateway';

import type { CoreBase, Generated } from '@seedcord/gateway';

type Replies = Generated<typeof Tags>['replies'];

export class Tags extends Plugin {
    public static readonly id = 'seedcord-tags';

    private replies = new Map<string, string>();

    public constructor(
        host: CoreBase,
        private readonly dir: string
    ) {
        super(host);
    }

    public override async init(): Promise<void> {
        this.replies = await this.read();
    }

    public override async codegen(): Promise<{
        replies: Record<string, true>;
    }> {
        const names = [...(await this.read()).keys()];
        return {
            replies: Object.fromEntries(
                names.map((name) => [name, true] as const)
            )
        };
    }

    public tag(name: keyof Replies): string {
        return this.replies.get(name) ?? name;
    }

    private async read(): Promise<Map<string, string>> {
        const replies = new Map<string, string>();
        for await (const { bytes } of readFiles(this.dir)) {
            const file: Record<string, string> = JSON.parse(
                bytes.toString()
            );
            for (const [name, text] of Object.entries(file)) {
                replies.set(name, text);
            }
        }
        return replies;
    }
}
```

`codegen()` reads the same files `init()` does, through one `read()` method, and returns each tag's name set to `true`. `tag()` only needs the names, but an object needs a value for each key, so `true` fills it. If a bot attaches it as `tags` and its `tags/server.json` holds `{ "rules": "Be nice.", "welcome": "Hi!" }`, codegen adds this row for your plugin to `PluginTypes` in the bot's file:

```ts title="src/seedcord-gen.ts" output
interface PluginTypes {
    'seedcord-tags': { replies: { rules: true; welcome: true } };
}

// at the end of the file
export type PluginTypeChecks = {
    'seedcord-tags': [
        Fits<
            (typeof Bot)['tags'],
            { replies: { rules: true; welcome: true } }
        >
    ];
};
```

Codegen also writes the row at the end of the file, in `PluginTypeChecks`, inside one `Fits` for each key the bot attached your plugin under. If the row doesn't match your `codegen()` return type, the bot's type check fails on that `Fits`. Your plugin only reads the row in `PluginTypes`.

`Replies` reads its keys from that row, so `tag()` accepts `'rules'` or `'welcome'`, and the bot author's editor offers both:

```ts twoslash
// @noErrors
import { Plugin } from '@seedcord/gateway';

import type { Generated } from '@seedcord/gateway';

declare module '@seedcord/gateway' {
    interface PluginTypes {
        'seedcord-tags': { replies: { rules: true; welcome: true } };
    }
}

type Replies = Generated<typeof Tags>['replies'];

declare class Tags extends Plugin {
    public static readonly id: 'seedcord-tags';
    public override init(): Promise<void>;
    public override codegen(): Promise<{
        replies: Record<string, true>;
    }>;
    public tag(name: keyof Replies): string;
}

declare const tags: Tags;
// ---cut---
tags.tag('
//        ^|
```

Before codegen first runs in a bot, [`Generated`](ref:core/Generated) falls back to the return type you declared, `Record<string, true>` here, so `tag()` takes any string.

<Callout type="warning">

Tell your users in your README to run `seedcord codegen` after they add a tag, and after they upgrade to a release of your plugin that changes what `codegen()` returns. Until they run it, a new key fails to compile. After such an upgrade, their type check fails on your row in `PluginTypeChecks` until codegen rewrites it.

</Callout>

The sample extends the gateway `Plugin`, so it only attaches to a gateway bot. To support both transports, import `Plugin` and `Generated` from `@seedcord/core/plugin` and `readFiles` from `@seedcord/utils`, as the [page on loading a bot's files](/writing-plugins/files) explains.

## Typing more than keys

Say your tags carry placeholders, like `"welcome": "Welcome {name}!"`. `tag('welcome')` should then require a `name`. Return each name with the list of its placeholders, and type `tag()` from that list. Only `codegen()` and `tag()` change, plus a helper:

```ts twoslash title="src/plugins/Tags.ts"
// ---cut-start---
import { Plugin, readFiles } from '@seedcord/gateway';

import type { CoreBase, Generated } from '@seedcord/gateway';

type Replies = Generated<typeof Tags>['replies'];

// ---cut-end---
export class Tags extends Plugin {
    // ...id, the constructor, init() and read() from above
    // ---cut-start---
    public static readonly id = 'seedcord-tags';

    private replies = new Map<string, string>();

    public constructor(
        host: CoreBase,
        private readonly dir: string
    ) {
        super(host);
    }

    public override async init(): Promise<void> {
        this.replies = await this.read();
    }

    private async read(): Promise<Map<string, string>> {
        const replies = new Map<string, string>();
        for await (const { bytes } of readFiles(this.dir)) {
            const file: Record<string, string> = JSON.parse(
                bytes.toString()
            );
            for (const [name, text] of Object.entries(file)) {
                replies.set(name, text);
            }
        }
        return replies;
    }
    // ---cut-end---

    public override async codegen(): Promise<{
        replies: Record<string, string[]>;
    }> {
        const entries = [...(await this.read())].map(
            ([name, text]) =>
                [name, Tags.placeholdersIn(text)] as const
        );
        return { replies: Object.fromEntries(entries) };
    }

    public tag<Name extends keyof Replies>(
        name: Name,
        values: Record<Replies[Name][number], string>
    ): string {
        const given = new Map(Object.entries<string>(values));
        const text = this.replies.get(name) ?? name;
        return text.replace(
            /\{(\w+)\}/g,
            (match, name: string) => given.get(name) ?? match
        );
    }

    // "Welcome {name}!" gives ['name']
    private static placeholdersIn(text: string): string[] {
        return (
            text.match(/\{\w+\}/g)?.map((p) => p.slice(1, -1)) ?? []
        );
    }
}
```

With `"welcome": "Welcome {name}!"` and `"rules": "Be nice."`, codegen writes `{ rules: []; welcome: ['name'] }`. `Replies['welcome'][number]` is `'name'`, so `tag('welcome')` needs a `name`. `tag('rules')` takes an empty object:

```ts twoslash
// @errors: 2345
import { Plugin } from '@seedcord/gateway';

import type { Generated } from '@seedcord/gateway';

declare module '@seedcord/gateway' {
    interface PluginTypes {
        'seedcord-tags': {
            replies: { rules: []; welcome: ['name'] };
        };
    }
}

type Replies = Generated<typeof Tags>['replies'];

declare class Tags extends Plugin {
    public static readonly id: 'seedcord-tags';
    public override init(): Promise<void>;
    public override codegen(): Promise<{
        replies: Record<string, string[]>;
    }>;
    public tag<Name extends keyof Replies>(
        name: Name,
        values: Record<Replies[Name][number], string>
    ): string;
}

declare const tags: Tags;
// ---cut---
tags.tag('welcome', { name: 'Ada' });
tags.tag('rules', {});
tags.tag('welcome', {});
```

## Getting the type you want

`codegen()` returns plain data, and you shape it into the type your methods take. In this table, `Field` stands for the field you read off `Generated<typeof YourPlugin>`, like `Replies` above.

{/* prettier-ignore-start */}

| you want | return | read it as |
| --- | --- | --- |
| a union of names | an object, `{ rules: true, welcome: true }` | `keyof Field` is `'rules' \| 'welcome'` |
| a union of values | an array, `['faq', 'mod']` | `Field[number]` is `'faq' \| 'mod'` |
| data for each name | an object of data, `{ welcome: ['name'] }` | `Field[Key]` is `['name']` for `'welcome'` |
| a fixed value | a string, a finite number, a boolean, or `null` | `Field` is that literal, like `'faq'` |
| a nested shape | objects and arrays inside each other | the same shape, with object keys sorted |
| a class | a class a project file exports | `Field` is the class, and `InstanceType<Field>` is an instance of it |

{/* prettier-ignore-end */}

A few rules decide what you can return:

- **A class needs a file that exports it.** Codegen writes any exported value, a class or an object, as an import of that file, so the bot or your `codegen()` has to have imported the file. If your own package exports it, codegen imports it by package name. Declare exported data `as const` to keep its literal types.
- **Anything else has to be plain data.** A `Date`, a class instance, or a function that no file exports stops codegen with `CliPluginCodegenValue`.
- **Prefer an object over an array if a bot can attach your plugin twice.** Codegen merges two objects key by key. Two arrays have to match as a whole, or codegen stops with `CliPluginCodegenConflict`.
- **Return only what your types need.** Codegen writes every value into the bot's committed file. If you returned the reply text, `seedcord codegen --check` would fail each time someone rewords a tag.

## Returning classes

Say your plugin runs minigames, and a bot writes each game as a class in its `games` folder. A [`FolderExports`](ref:core/FolderExports) imports a folder and hands each matching export to your `register` callback when you call `load()` in `init()`. Its `scan()` imports the same folder for `codegen()` without registering anything. `codegen()` returns the game classes themselves, keyed by their class name:

```ts twoslash title="src/plugins/Arcade.ts"
import { FolderExports, Plugin } from '@seedcord/gateway';

import type { CoreBase, Generated } from '@seedcord/gateway';

export abstract class Game {
    public abstract start(channelId: string): Promise<void>;
}

type GameClass = new () => Game;
type Games = Generated<typeof Arcade>['games'];

function isGameClass(value: unknown): value is GameClass {
    return (
        typeof value === 'function' &&
        value.prototype instanceof Game
    );
}

export class Arcade extends Plugin {
    public static readonly id = 'seedcord-arcade';

    private readonly games = new Map<string, GameClass>();
    private readonly files: FolderExports<GameClass>;

    public constructor(host: CoreBase, dir: string) {
        super(host);
        this.files = new FolderExports({
            dir,
            is: isGameClass,
            register: (Game) => this.games.set(Game.name, Game),
            unregister: (Game) => this.games.delete(Game.name),
            logger: this.logger
        });
    }

    public override async init(): Promise<void> {
        await this.files.load();
    }

    public override async codegen(): Promise<{
        games: Record<string, GameClass>;
    }> {
        const games: Record<string, GameClass> = {};
        for (const Game of await this.files.scan()) {
            games[Game.name] = Game;
        }
        return { games };
    }

    public create<Name extends keyof Games & string>(
        name: Name
    ): InstanceType<Games[Name]> {
        const GameClass = this.games.get(name);
        if (!GameClass) throw new Error(`no game called ${name}`);
        return new GameClass();
    }
}
```

If a bot attaches it as `arcade` and its `games/Trivia.ts` exports a `Trivia` class that extends `Game`, codegen writes it as an import of that file:

```ts title="src/seedcord-gen.ts" output
interface PluginTypes {
    'seedcord-arcade': {
        games: {
            Trivia: (typeof import('./games/Trivia'))['Trivia'];
        };
    };
}
```

`Games['Trivia']` is the class itself, so `create('Trivia')` returns `InstanceType<Games['Trivia']>`, a `Trivia` with every method the bot wrote on it. [Mongoose](/plugins/mongoose-services#typing-the-services) types its services the same way.

## The id

Every plugin's row in the bot's `PluginTypes` is keyed by its id. You declare the id on the class because your package reads its own row with `Generated<typeof Tags>` when it builds before any bot has picked an attach key. Use your package's name, like `'seedcord-tags'` here, so another plugin doesn't write the same id.

Write it `static readonly`. Without `readonly`, TypeScript types the id as `string`, and each field of `Generated` becomes a message telling you to add `readonly`.

A bot can attach your plugin under two keys, like two `Tags` for two folders. Both share the one row, so codegen merges what the two `codegen()` calls returned. Two folders that hold the same tag have to return the same value for it.

## codegen() runs without init()

`seedcord codegen` constructs the bot and never calls `init()`. A CI job running `seedcord codegen --check` doesn't call it either. Anything `init()` sets up, like a connection, doesn't exist yet. Inside `codegen()`, use only what the constructor stored and the bot's files.

[`readFiles`](ref:utils/readFiles) and `scan()` work there since the CLI sets the bot's `root` before it loads your plugin. `readFiles` still needs the folder listed in the bot's [`files`](/build/data-files), the same as when the bot runs.

For a server bot, `seedcord dev` writes the file after the bot has started and `init()` has run. An edge bot runs in workerd. For codegen, dev loads a separate copy in Node, and that copy never calls `init()`. A `codegen()` that reads `init()` state works only for a server bot under `seedcord dev`. It fails under `seedcord codegen`, in CI, and on an edge bot, so test yours with `seedcord codegen`.

## When codegen stops

`seedcord codegen` collects every plugin's problem from one run and reports them together. `seedcord dev` logs them and keeps the bot running.

{/* prettier-ignore-start */}

| error | when |
| --- | --- |
| `CliPluginCodegenNoId` | the class has a `codegen()` and no `id` |
| `CoreDuplicateName` | two different classes use one id |
| `CliPluginCodegenThrew` | your `codegen()` threw. It includes the plugin's key and your error's message |
| `CliPluginCodegenValue` | your `codegen()` returned a value codegen can't write, at the path it gives |
| `CliPluginCodegenConflict` | two attachments of your plugin returned different values for one field. It gives both keys and the field |

{/* prettier-ignore-end */}
