---
title: Select menus
description: One select menu carries options you write. The other kinds resolve users, roles, or channels for you.
---

A select menu is a dropdown someone picks from. One kind carries options you write yourself. For the rest, Discord resolves the picks into users, roles, channels, or a mix of the three, then sends the objects behind those ids. Every kind gets its own handler base, and each one routes the way a button does.

```ts twoslash title="src/components/TopicPicker.ts"
import { StringSelectMenuBuilder } from '@discordjs/builders';
import { CustomId, RowComponent } from '@seedcord/gateway';

export const TopicsId = new CustomId('topics').snowflake('userId');

export class TopicPicker extends RowComponent<'menu_string'> {
    constructor(userId: string) {
        super('menu_string');

        this.instance.addComponents(
            new StringSelectMenuBuilder()
                .setCustomId(TopicsId.encode({ userId }))
                .setPlaceholder('Pick your topics')
                .setMinValues(1)
                .setMaxValues(3)
                .addOptions(
                    { label: 'Releases', value: 'releases' },
                    { label: 'Outages', value: 'outages' },
                    { label: 'Events', value: 'events' }
                )
        );
    }
}
```

Discord allows one select menu per row and nothing beside it. `setMinValues` and `setMaxValues` bound how many someone picks. Both default to 1, and Discord caps each at 25.

## Routing the pick

The menu above carries options you wrote, so it routes through [`@StringMenuRoute`](ref:core/StringMenuRoute) to a `StringMenuHandler`. Pass the same [`CustomId`](ref:custom-id/CustomId) definitions to the decorator and the generic. Passing different ones is a compile error.

```ts twoslash title="src/handlers/Topics.ts"
import {
    CustomId,
    StringMenuHandler,
    StringMenuRoute
} from '@seedcord/gateway';

// in your project this is defined in the component file that mints it
const TopicsId = new CustomId('topics').snowflake('userId');

@StringMenuRoute(TopicsId)
export class Topics extends StringMenuHandler<[typeof TopicsId]> {
    public async execute(): Promise<void> {
        const { userId } = this.params;
        const picked = this.values;
        //    ^?

        await this.update(
            `<@${userId}> now follows ${picked.join(', ')}.`
        );
    }
}
```

`this.values` holds what someone picked. On a string menu those are the values you set on the options. `this.params`, `this.match`, `this.update`, and `this.deferUpdate` all work as they do on [Buttons](/components/buttons).

## The resolving kinds

The resolving kinds fill `this.values` with ids and carry the objects those ids point at. A user menu routes through [`@UserMenuRoute`](ref:core/UserMenuRoute) to a `UserMenuHandler`, which declares `this.users` and `this.members` beside the ids.

```ts twoslash title="src/handlers/Assign.ts"
import {
    CustomId,
    UserMenuHandler,
    UserMenuRoute
} from '@seedcord/gateway';

const AssignId = new CustomId('assign').snowflake('roleId');
// ---cut---
@UserMenuRoute(AssignId)
export class Assign extends UserMenuHandler<[typeof AssignId]> {
    public async execute(): Promise<void> {
        const { roleId } = this.params;
        const chosen = this.users;
        //    ^?

        await this.update(
            `Assigning <@&${roleId}> to ${chosen.size} member(s).`
        );
    }
}
```

Each base declares only the members its menu resolves.

{/* prettier-ignore-start */}

| base | decorator | what the handler carries |
| --- | --- | --- |
| `StringMenuHandler` | [`@StringMenuRoute`](ref:core/StringMenuRoute) | `this.values` |
| `UserMenuHandler` | [`@UserMenuRoute`](ref:core/UserMenuRoute) | `this.values`, `this.users`, `this.members` |
| `RoleMenuHandler` | [`@RoleMenuRoute`](ref:core/RoleMenuRoute) | `this.values`, `this.roles` |
| `ChannelMenuHandler` | [`@ChannelMenuRoute`](ref:core/ChannelMenuRoute) | `this.values`, `this.channels` |
| `MentionableMenuHandler` | [`@MentionableMenuRoute`](ref:core/MentionableMenuRoute) | `this.values`, `this.users`, `this.members`, `this.roles` |

{/* prettier-ignore-end */}

Read a member that the base leaves out and the compiler stops you at the property.

Discord resolves `this.members` only inside a guild, so it comes back empty in a DM. A mentionable menu accepts users and roles together. `this.users` and `this.roles` each hold whatever matched, so either one can be empty.

<Callout type="transport">

Both transports return a `Collection` keyed by id. The values differ. Gateway returns live discord.js `User`, `GuildMember`, `Role`, and `Channel` instances. Http returns the `discord-api-types` payloads Discord sent.

</Callout>

## One handler, several menus

Two menus of the same kind can share one class. Name every id on the decorator, then give `this.match` an arm per prefix.

```ts twoslash title="src/handlers/Filters.ts"
import {
    CustomId,
    StringMenuHandler,
    StringMenuRoute
} from '@seedcord/gateway';

const RegionId = new CustomId('region').snowflake('userId');
const LanguageId = new CustomId('language').snowflake('userId');
// ---cut---
@StringMenuRoute(RegionId, LanguageId)
export class Filters extends StringMenuHandler<
    [typeof RegionId, typeof LanguageId]
> {
    public async execute(): Promise<void> {
        const picked = this.values.join(', ');

        await this.match({
            region: ({ userId }) =>
                this.update(`<@${userId}> is in ${picked}.`),
            language: ({ userId }) =>
                this.update(`<@${userId}> reads ${picked}.`)
        });
    }
}
```

<Callout type="warning">

A string menu and a user menu need a handler each. Point one kind's decorator at another kind's base and the compiler stops you at the decorator line with `the decorator does not match the handler kind`.

</Callout>

Putting several menus on one message takes a row each. Give each menu its own id. Route them to the same handler when they share a kind.
