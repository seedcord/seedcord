Here is a slash command, and the code that runs when someone uses it.

```ts twoslash title="src/commands/Ping.ts"
import {
    BuilderComponent,
    RegisterCommand
} from '@seedcord/gateway';

@RegisterCommand('global')
export class Ping extends BuilderComponent<'command'> {
    constructor() {
        super('command');

        this.instance
            .setName('ping')
            .setDescription('Check that the bot is answering')
            .addBooleanOption((option) =>
                option
                    .setName('detailed')
                    .setDescription('Include process uptime')
            );
    }
}
```

<Callout type="note">
    [BuilderComponent](ref:core/BuilderComponent) wraps discord.js's
    builders. `this.instance` is the builder itself, typed to the
    kind you pass to `super()`. A command declared this way is
    guild-only until you call `setContexts`.
</Callout>

```ts twoslash hovers title="src/handlers/Ping.ts"
import { SlashHandler, SlashRoute } from '@seedcord/gateway';

@SlashRoute('ping')
export class Ping extends SlashHandler<'ping'> {
    public async execute(): Promise<void> {
        const detailed = this.options.getBoolean('detailed');

        await this.reply(
            detailed === true ? 'Pong, at length' : 'Pong'
        );
    }
}
```

Hover `getBoolean` and the type comes back `boolean | null`. You declared that option once, on the command above, and the accessor reads its name and its shape from there.

## A typo stops the build

```ts twoslash title="src/handlers/Ping.ts"
// @errors: 2345
import { SlashHandler, SlashRoute } from '@seedcord/gateway';

@SlashRoute('ping')
export class Ping extends SlashHandler<'ping'> {
    public async execute(): Promise<void> {
        const detailed = this.options.getBoolean('detaild');
    }
}
```

`tsc` reports that before the bot ever connects. So does the route string. A handler for a command you never declared fails to compile.

## What comes with it

**Commands and components.** A command is a class, and a [SlashHandler](ref:gateway/SlashHandler) runs when someone uses it. Subcommands, groups, autocomplete, and both context menus route the same way. Buttons, select menus, and modals reach a [ComponentHandler](ref:gateway/ComponentHandler) through their customId, and [CustomId](ref:core/CustomId) packs your fields into the hundred characters Discord allows and decodes them again on the click.

**Replying.** `reply()` sends the first response, and `defer()`, `edit()`, `followUp()`, `send()`, and `delete()` cover the rest, all on [RepliableHandler](ref:gateway/RepliableHandler). seedcord records which of those you already called and throws when the next one is illegal with a useful error message.

**Refusing.** Gates run before `execute()` and refuse by throwing. [Notice](ref:core/Notice) shows the user a card you wrote. [Fault](ref:core/Fault) shows a generic apology and reports the real error to you. [Silence](ref:core/Silence) drops it. Permission gates, role gates, and [cooldowns](ref:core/Cooldown) come with the framework, and you write your own with [defineGate](ref:core/defineGate).

**Events.** An [EventHandler](ref:gateway/EventHandler) takes one gateway event and reads `this.event`, or takes several and branches with `this.match`, where each arm receives that event's own payload. The [Bus](ref:core/Bus) underneath carries seedcord's own timings, so you can subscribe to them.

**Plugins.** `attach()` takes a key you pick and a [Plugin](ref:gateway/Plugin). Codegen types that key onto your core, and `this.core.<key>` resolves everywhere.

**Tooling.** `seedcord dev` runs a full-screen terminal, and hot reload swaps changed modules while the gateway connection stays open. `seedcord codegen` writes the types behind `this.options`. Two ESLint plugins catch the payloads Discord rejects before you send them.

## Two transports

You pick one when you scaffold.

`@seedcord/gateway` holds a websocket connection through discord.js, which is how message, member, voice, and reaction events reach you. `@seedcord/http` answers Discord's interactions endpoint, where only interactions arrive.

Everything above is the same code on both. A command written for one transport differs from the other by its import line.

## Where it stands

seedcord is pre-1.0, so a minor version can break you. Read the changelog before you bump. Most of the large changes I had planned are done already.

<Callout type="warning">
    The http transport's edge build for Cloudflare Workers is a work
    in progress and cannot be used yet. Http on Node works.
</Callout>

Every symbol here has its full signature on [the reference site](https://docs.seedcord.org). This guide covers what a signature cannot tell you.
