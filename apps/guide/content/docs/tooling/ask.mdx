---
title: Searching the guide
description: Search the guide from your terminal with seedcord ask, using a question, a pasted error, or an error code, and get links to the sections that match.
---

`seedcord ask` searches the guide from your terminal. Use it to look up an error you just hit, or to check whether seedcord already ships something before you write it yourself. A coding agent can run it too.

It runs the search behind the **Related** results in the guide's search dialog. That search matches by meaning, so your question doesn't have to use the guide's words.

<Shell exec="seedcord ask how do i stop someone spamming a command" />

The answer lists each matching page with its matching sections, and a link to each section. Before your bot exists, you can run it outside a project through `pnpm dlx`.

<Callout type="warning">

Quote the question if it contains a flag that the CLI reads, like `--help`, `-h`, `--version`, `-V`, or `--verbose`. Quote it too if it has a character that your shell treats as special, like `?` or `[` in zsh. The CLI treats other words that look like flags as part of the question.

</Callout>

A stable release of the CLI searches `seedcord.org/guide`. A prerelease, a version with a `-` in it like `0.14.0-next.0`, searches `next.seedcord.org/guide` because that site has the pages for code that isn't in a stable release yet.

## Pasting an error

Paste the whole error as the question. `seedcord ask` removes the stack frames, then searches the first 500 characters of what's left. If the command shortens your text, the answer says so.

A seedcord error starts with its code in brackets, like `[3116]`. The guide's pages use the error's name, so the command looks up the name for you:

{/* prettier-ignore-start */}

| you run | what it searches for |
| --- | --- |
| `seedcord ask "[3116]"` | `CliDependencyMissing` |
| `seedcord ask 3116` | `CliDependencyMissing` |
| `seedcord ask error 3116` | `CliDependencyMissing` |
| `seedcord ask what is 3116` | `CliDependencyMissing` |
| `seedcord ask seedcord error 3116` | `seedcord error 3116 CliDependencyMissing` |

{/* prettier-ignore-end */}

The answer starts with `3116 is CliDependencyMissing`. Inside a longer question, the command doesn't read a bare four-digit number as an error code since it could be a port, year, or something else entirely. If that number is also an error code, the answer adds a command like `seedcord ask "error 3116"` that looks up the code.

## Running it from a script or an agent

Without a terminal attached, or with `CI` set, `seedcord ask` prints only the answer. Each page in the answer links to its Markdown copy and lists the matching headings so that a coding agent can read the page without its HTML. If nothing matches, the answer links `llms.txt`, the list of every page in the guide, and the command exits with code 0. Every failure below exits with code 1.

A project from `create-seedcord` tells coding agents to use this command in its `AGENTS.md`.

## When it fails

{/* prettier-ignore-start */}

| what happened | the error |
| --- | --- |
| your question is under 2 characters, or doesn't contain a letter or a number | `CliAskBadQuestion` |
| the guide search got too many requests or hit its daily limit, and the message says when to try again | `CliAskHasToWait` |
| the request failed, or took longer than 10 seconds | `CliAskFailed` |

{/* prettier-ignore-end */}

`CliAskHasToWait` and `CliAskFailed` print the guide's address, so you can open the guide and read it yourself.
