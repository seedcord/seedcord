---
title: Hot reload
description: Most saves swap in while your bot keeps its Discord connection, though a few files force a full restart.
---

Most of the time seedcord reloads a saved file on its own. It drops that one file, imports the fresh copy, then wires the new handlers in. Your bot keeps its connection to Discord through all of it, so you can immediately go back to Discord to test your changes.

A few files cannot work that way.

## Saves that need a restart

Saving any of these forces a full restart:

- `seedcord.config.ts`, since the CLI read it at startup
- any `package.json`
- any `tsconfig.json`
- any `.env`
- the two files `entry` and `instance` point at

Your bot keeps running the old code. The terminal switches to this.

```txt output
Restart required. Press r to restart.
```

Nothing restarts by itself. Press `r` once you are ready to lose the connection for a moment.

A plugin can add to that list too. The Kysely plugin registers your migrations folder, which [Writing your own](/plugins/your-own) covers under `registerCriticalFiles`.

You might want the same for some of your own files. The usual candidate opens a connection or computes something once at import, since a reload imports it again and runs that work a second time. `hmr.restart` takes glob patterns, matched against paths under `root`.

```ts twoslash title="seedcord.config.ts"
import { defineConfig } from 'seedcord';

export default defineConfig({
    root: './src',
    instance: './bot.ts',
    entry: './index.ts',
    hmr: {
        restart: ['config/**', 'constants.ts']
    }
});
```

## A save that does not compile

Typos happen. A file that throws on import would normally leave you without a working handler, so seedcord keeps the last good version live instead.

```txt output
Rolled back ./src/handlers/Ping.ts to the last-good version
```

Your old handler stays live until your next good save replaces it. Setting `hmr.rollback` to `false` turns that off. A broken file then drops its handlers, so the route stops answering until you fix it.

```ts twoslash title="seedcord.config.ts"
import { defineConfig } from 'seedcord';
// ---cut---
export default defineConfig({
    root: './src',
    instance: './bot.ts',
    entry: './index.ts',
    hmr: {
        rollback: false
    }
});
```

## Type errors while you work

`seedcord dev` runs your code without checking types first, so a type error only reaches you when your editor shows it. Turning on `hmr.typecheck` runs `tsc --watch` beside the bot. It reports what it finds on the `tsc` channel, which the log filters can reach.

```ts twoslash title="seedcord.config.ts"
import { defineConfig } from 'seedcord';
// ---cut---
export default defineConfig({
    root: './src',
    instance: './bot.ts',
    entry: './index.ts',
    hmr: {
        typecheck: true
    }
});
```

A second node process is the price, so it starts switched off. It also waits until your bot is ready. Your first login stays quick that way.

Pass an object when your build uses a different tsconfig.

```ts twoslash title="seedcord.config.ts"
import { defineConfig } from 'seedcord';
// ---cut---
export default defineConfig({
    root: './src',
    instance: './bot.ts',
    entry: './index.ts',
    hmr: {
        typecheck: { tsconfig: './tsconfig.build.json' }
    }
});
```
