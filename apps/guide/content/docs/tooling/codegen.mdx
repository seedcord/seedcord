[Commands](/commands) covers the slash routes `seedcord codegen` writes into `src/seedcord-gen.d.ts`. That file carries four other tables alongside them.

<Shell run="codegen" />

Every run rewrites the whole file from scratch. Whatever it finds in your project this time becomes the entire contents.

{/* prettier-ignore-start */}

| what it types | filled from |
| --- | --- |
| `SlashRegistry` | every command class in your `commands` folder |
| `UserContextMenuRegistry` | the same folder, for right-click commands on a user |
| `MessageContextMenuRegistry` | the same folder, for right-click commands on a message |
| `EmojiMap` | the `bot.emojis` block on your config |
| `Core` | the key you gave each attached plugin |

{/* prettier-ignore-end */}

The last one appears once you attach a plugin, which is what types `this.core.db`, for example. [Typing a plugin](/plugins/typing) covers it.

## Codegen builds your bot

To read your commands folder and your emoji block, codegen imports the module your `instance` setting points at. Constructing your bot runs your plugin setup, so their log lines turn up during a codegen run.

Your bot never starts, though. It stays offline for the whole run, so nothing you have written reaches Discord.

## Catching a stale file in CI

A stale generated file compiles against the wrong shapes, which your editor shows you and a pipeline misses. Passing `--check` renders the file in memory and compares it to the copy on disk.

<Shell exec="seedcord codegen --check" />

Matching output exits `0` in silence. A difference prints this and exits `1`.

```txt output
Augmentations are out of date. Run `seedcord codegen` and commit src/seedcord-gen.d.ts.
```

`--check` only reports, so fixing the drift needs a plain `seedcord codegen` run. The scaffold does not wire a script for it, which leaves it free for your own pipeline.

## Commands codegen passes over

A command class reaches the registry once it carries `@RegisterCommand`. Without the decorator codegen walks past it. Your route never appears in `SlashRegistry`, so the handler naming that route fails to compile.

Your commands folder can hold helpers and constants too. Codegen imports every file it finds there and keeps the exports that are decorated command classes, leaving the rest alone.

## Two commands, one name

Discord scopes command names per kind. seedcord holds you to the same rule. Two commands resolving to one slash route throw `CliCodegenDuplicateRoute`. Two context menus of one kind sharing a name throw `CliCodegenDuplicateContextMenu`. Both errors name the two files, so you know which one to rename.

A commands folder codegen cannot read throws `CliCodegenCommandsDirUnreadable`. Writing an empty registry there would pass `--check` against a file that is already stale.
