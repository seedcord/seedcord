[Commands](/commands) covers the slash routes `seedcord codegen` writes into `src/seedcord-gen.d.ts`. That file carries four other tables alongside them.

<Shell run="codegen" />

Every run rewrites the whole file from scratch.

{/* prettier-ignore-start */}

| what it types | filled from |
| --- | --- |
| [`SlashRegistry`](ref:core/SlashRegistry) | every command class in your `commands` folder |
| [`UserContextMenuRegistry`](ref:core/UserContextMenuRegistry) | the same folder, for right-click commands on a user |
| [`MessageContextMenuRegistry`](ref:core/MessageContextMenuRegistry) | the same folder, for right-click commands on a message |
| [`EmojiMap`](ref:types/EmojiMap) | the `bot.emojis` block on your config |
| [`Core`](ref:gateway/Core) | the key you gave each attached plugin |

{/* prettier-ignore-end */}

`Core` only appears once you attach a plugin. It types `this.core.db`, for example. [Typing a plugin](/plugins/typing) covers it.

## Codegen constructs your bot

To read your commands folder and your emoji block, codegen imports the module your `instance` setting points at. Constructing your bot runs your plugin setup. Those plugin log lines during a codegen run come from there.

Your bot never starts, though. It stays offline for the whole run, so nothing you have written reaches Discord.

## Catching a stale file in CI

Some drift breaks the build for you. Add a command without rerunning codegen, then the handler naming its route fails to compile. Your editor flags it immediately.

Other drift compiles perfectly. Delete a command and the registry keeps its old entry, still typing a route your bot stopped answering. Passing `--check` renders the file in memory and compares it to the copy on disk, which catches the quiet kind.

<Shell exec="seedcord codegen --check" />

Matching output exits `0` in silence. A difference prints this and exits `1`.

```txt output
Augmentations are out of date. Run `seedcord codegen` and commit src/seedcord-gen.d.ts.
```

`--check` only reports, so fixing the drift needs a plain `seedcord codegen` run. The scaffold does not wire a script for it, which leaves it free for your own pipeline.

## Commands codegen passes over

A command class reaches the registry once it carries `@RegisterCommand`. Without the decorator codegen skips that export entirely. Your route never appears in `SlashRegistry`, so the handler naming it fails to compile.

Your commands folder can hold helpers and constants too. Codegen imports every file it finds there. It keeps the exports that are decorated command classes and ignores the rest.

## Two commands, one name

Discord scopes command names per kind. seedcord holds you to the same rule. Two commands resolving to one slash route throw `CliCodegenDuplicateRoute`. Two context menus of one kind sharing a name throw `CliCodegenDuplicateContextMenu`. Both errors name the two files, so you know which one to rename.

A commands folder that codegen cannot read throws `CliCodegenCommandsDirUnreadable`. Writing an empty registry there would pass `--check` against a file that is already stale.
