[`@seedcord/plugin-mongoose`](ref:plugin-mongoose) connects to MongoDB and loads your service classes when the bot starts, then disconnects when it stops. Your schemas and queries are plain [Mongoose](https://mongoosejs.com/docs/).

<Shell add="@seedcord/plugin-mongoose mongoose" />

```ts twoslash title="src/bot.ts"
import { Seedcord } from '@seedcord/gateway';
import { Mongoose } from '@seedcord/plugin-mongoose';
import { GatewayIntentBits } from 'discord.js';
import { Converters, Envapter } from 'envapt';

export const seedcord = new Seedcord({
    bot: {
        clientOptions: { intents: [GatewayIntentBits.Guilds] },
        interactions: { path: './handlers' },
        commands: { path: './commands' },
        events: { path: null }
    },
    subscribers: { path: null }
}).attach('db', Mongoose, {
    path: './services',
    uri: Envapter.getRequired('MONGO_URI', Converters.String),
    name: 'seedcord',
    connectionOptions: { serverSelectionTimeoutMS: 5000 },
    timeout: 15_000
});

export default seedcord;
```

This sample builds a gateway bot. The same `attach` call works on an http `Seedcord` from `@seedcord/http` that runs on a server. On Cloudflare Workers it's a compile error because the plugin [needs a server](/plugins#a-plugin-declares-where-it-runs), and a cast that bypasses the check throws `CorePluginScopeMismatch`.

The sample reads `uri` with envapt's `Envapter.getRequired`, which throws if `MONGO_URI` is unset. TypeScript rejects `process.env.MONGO_URI` there because its type is `string | undefined`. [Env files and modes](/build/env) has the details.

## The options

{/* prettier-ignore-start */}

| option | required | what it sets |
| --- | --- | --- |
| `path` | yes | the folder that the plugin scans for service classes. A relative path is relative to `root`, and the folder has to be inside it, as [the folder rules](/plugins) describe |
| `uri` | yes | the MongoDB connection string |
| `name` | yes | the database, passed to mongoose as `dbName` |
| `connectionOptions` | no | any `mongoose.ConnectOptions`, merged over what the plugin sets |
| `timeout` | no | how long disconnecting may take during shutdown, in milliseconds. Defaults to 10000 |

{/* prettier-ignore-end */}

`connectionOptions` merges last over everything the plugin passes to `mongoose.connect()`, so you can override any setting the plugin chose. A `dbName` key in that object replaces the database your `name` picked.

<Callout type="warning">

When the environment is `production`, the plugin adds `tls: true` and `ssl: true`. seedcord reads the environment from the first of `ENVIRONMENT`, `ENV`, `NODE_ENV`, or `MODE` that you set. If you run production mode against a local database without TLS, the connection fails, so set `tls: false` and `ssl: false` in `connectionOptions`.

</Callout>

## Startup and shutdown

By hand, a bot that fails halfway through startup would leave its MongoDB connection open. The mongoose plugin closes that connection for you. `init()` connects, then loads every service class from `path`. If either step fails, `init()` closes the connection before it rethrows the error.

If the connection fails, `init()` throws `PluginConnectionFailed`. Its message includes the database from your `name` option and mongoose's own message, and the full mongoose error is in its `cause`.

`dispose()` clears the services and every model the plugin built, then closes the connection. If closing fails, `dispose()` throws `PluginDisconnectFailed`.

## The mongoose instance

You write most of your queries in [service classes](/plugins/mongoose-services). Some work doesn't belong in a service, like checking whether the bot is still connected to MongoDB. For that, read the plugin's [`connection`](ref:plugin-mongoose/Mongoose.connection), the Mongoose instance that `mongoose.connect()` returned. Its own `connection` property is Mongoose's `Connection` object.

```ts twoslash
import { SlashHandler, SlashRoute } from '@seedcord/gateway';

import type { Mongoose } from '@seedcord/plugin-mongoose';

declare module '@seedcord/gateway' {
    interface Core {
        db: Mongoose;
    }
}

@SlashRoute('history')
class History extends SlashHandler<'history'> {
    public async execute(): Promise<void> {
        // ---cut---
        const state = this.core.db.connection.connection.readyState;

        await this.reply(`Connection state ${String(state)}.`);
        // ---cut-after---
    }
}
```

`readyState` is `1` while the bot is connected. `this.core.db` only has a type once you've run [`seedcord codegen`](/plugins/typing).

<Callout type="warning">

`connection` and `services` are only ready after `init()` resolves. Reading either one before that, or after `dispose()`, throws `PluginNotReady`.

</Callout>
