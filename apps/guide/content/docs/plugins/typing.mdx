---
title: Typing a plugin
description: What codegen writes so this.core.db compiles.
---

You attached a plugin and `this.core.db` is a compile error. The property is there while the bot runs. `seedcord codegen` writes its type into `src/seedcord-gen.d.ts`.

```ts twoslash title="src/handlers/History.ts"
// @errors: 2339
import { SlashHandler, SlashRoute } from '@seedcord/gateway';

// ---cut---
@SlashRoute('history')
export class History extends SlashHandler<'history'> {
    public async execute(): Promise<void> {
        await this.reply(String(this.core.db));
    }
}
```

## What codegen writes

One row per attached key, sorted by key.

```ts title="src/seedcord-gen.d.ts" output
// Generated by `seedcord codegen`. Do not edit by hand.
// Run `seedcord codegen` after changing your commands, plugins, or emoji config.

import type Bot from './bot';

// prettier-ignore
declare module '@seedcord/gateway' {
    interface Core {
        db: (typeof Bot)['db'];
    }
}

export {};
```

`Bot` is the default export of the file your `instance` key names. Each row takes its type from the bot you built there. Export that bot only as a named const and codegen stops with `Seedcord instance must default export an object with a start() method.`

Attaching nothing leaves the [`Core`](ref:gateway/Core) block out.

The `declare module` line names the package you import `Seedcord` from, so an http bot's file opens `declare module '@seedcord/http'`.

## When to run it

Run `seedcord codegen` after you attach a plugin, remove one, or rename a key.

`seedcord dev` regenerates the file when you answer `y` to its re-register prompt. That prompt reads your command files, so changing what you attach never raises it.
