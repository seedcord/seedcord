title: Typing a plugin
description: Run seedcord codegen to type the plugins you attached on this.core, and learn when to run it again after you change one.

You've attached the plugin, but `this.core.db` still fails to compile. The property is there when the bot runs, so only the types are missing. `attach` returns a bot typed with `db`, but a handler reads `this.core`. seedcord declares the type of `this.core` in its own package, which never imports your bot file.

Without codegen, you'd declare those types by hand in a `declare module` block and update it each time you rename a key. `seedcord codegen` writes that block for you into `src/seedcord-gen.ts`.

```ts twoslash title="src/handlers/History.ts"
// @errors: 2339
import { SlashHandler, SlashRoute } from '@seedcord/gateway';

@SlashRoute('history')
export class History extends SlashHandler<'history'> {
    public async execute(): Promise<void> {
        await this.reply(String(this.core.db));
    }
}
```

TypeScript reports "Property 'db' does not exist on type 'Core'" on `this.core.db`. Nothing is wrong with the handler itself.

## What codegen writes

Every key you attached becomes one row on [`Core`](ref:gateway/Core), sorted by key. A group takes one row for all the plugins inside it. The same file also holds your command and emoji registries, which this sample skips.

```ts title="src/seedcord-gen.ts" output
// Generated by `seedcord codegen`. Do not edit by hand.
// Run `seedcord codegen` after changing your commands, plugins, or emojis.

import type Bot from './bot';
import type { AttachedPlugin } from '@seedcord/gateway';

type Fits<
    Plugin extends { codegen(): Promise<unknown> },
    Row extends Awaited<ReturnType<Plugin['codegen']>>
> = Row;

// prettier-ignore
declare module '@seedcord/gateway' {
    interface Core {
        db: AttachedPlugin<(typeof Bot)['db']>;
        i18n: AttachedPlugin<(typeof Bot)['i18n']>;
    }
    // SlashRegistry, the context menu registries, and EmojiMap follow
    interface PluginTypes {
        '@seedcord/plugin-i18n': { messages: { bye: {}; greet: { user: 'text' } } };
    }
    interface DispatchMemberValues {
        t: Awaited<ReturnType<(typeof Bot)['i18n']['dispatchMembers']['t']>>;
    }
}

// prettier-ignore
export type PluginTypeChecks = {
    '@seedcord/plugin-i18n': [Fits<(typeof Bot)['i18n'], { messages: { bye: {}; greet: { user: 'text' } } }>];
};

export {};
```

`Bot` is the default export of the file that your `instance` config key points to. The file has three kinds of rows for plugins, and each block appears once it has a row.

<Callout type="transport">

Each transport package declares its own `Core`, so the `declare module` line uses the package you import [`Seedcord`](ref:gateway/Seedcord) from. A gateway bot's file uses `declare module '@seedcord/gateway'`, and an http bot's uses `declare module '@seedcord/http'`.

</Callout>

### The Core rows

The `Core` block appears once you've attached something. Each row reads its type from `Bot`, so `db` has the type `attach` returns, minus the members only seedcord calls, like [`init()`](ref:core/Plugin.init). [Calling it from a handler](/writing-plugins#calling-it-from-a-handler) lists all of them.

[`AttachedPlugin`](ref:core/AttachedPlugin) is the type that omits those members. It also omits the class's private members, so `this.core.db` isn't assignable to a parameter typed as the [`Mongoose`](ref:plugin-mongoose/Mongoose) class. To pass it to a function of your own, type that parameter as `AttachedPlugin<Mongoose>`.

These rows need the bot file's default export to be the value `attach` returns:

- If you [export the bot without it](/plugins#no-plugin-types-in-your-handler), `this.core.db` has the type `any`.
- If you export the bot only as a named const, codegen stops with the code `CliInstanceInvalid` before it writes anything.

### The PluginTypes rows

[`PluginTypes`](ref:core/PluginTypes) appears once a plugin has written a row. It holds the types that each plugin's [`codegen()`](ref:core/Plugin.codegen) returns from your project's files, keyed by the plugin's `static id`, like `'@seedcord/plugin-i18n'`.

The [i18n plugin](/plugins/i18n), attached as `i18n`, writes the row in the sample. It lists the message keys in your `locales` folder and the variables each one takes, so `this.t()` accepts `'bye'` or `'greet'` and rejects a typo.

[Writing types from codegen](/writing-plugins/codegen) covers the `PluginTypeChecks` type at the end of the file, and how to add a row from your own plugin.

### The DispatchMemberValues rows

[`DispatchMemberValues`](ref:types/DispatchMemberValues) appears once a plugin has [`dispatchMembers`](/writing-plugins#adding-a-value-to-every-handler), and it gets one row for each key in them. The `t` row types `this.t` on every handler.

## When to run it

The generated file only changes when codegen runs, so a stale one either misses a new key or still declares a key you removed.

- In `seedcord dev`, press `g` to run codegen after you add a file that a plugin reads during codegen, like a Mongoose service. Press `r` to restart the bot after you attach a plugin or rename its key since dev rewrites the file when the bot starts.
- Outside dev, run `seedcord codegen`.
- In CI, `seedcord codegen --check` throws `CliCodegenOutOfDate` when the file is stale.

Once codegen has run, your editor offers `db` on `this.core`.

```ts twoslash
// @noErrors
import { SlashHandler, SlashRoute } from '@seedcord/gateway';
import type { AttachedPlugin } from '@seedcord/gateway';
import type { Mongoose } from '@seedcord/plugin-mongoose';

declare module '@seedcord/gateway' {
    interface Core {
        db: AttachedPlugin<Mongoose>;
    }
}

@SlashRoute('history')
export class History extends SlashHandler<'history'> {
    public async execute(): Promise<void> {
        // ---cut---
        this.core.
        //        ^|
        // ---cut-after---
    }
}
```

[The lifecycle page](/plugins/lifecycle) covers whether the plugin has started by the time your handler runs.

## Referenced directly or indirectly in its own initializer

TypeScript reports this error when a plugin's option reads the bot that the plugin gets attached to.

```ts twoslash title="src/bot.ts"
// @errors: 7022 7023 2345
// ---cut-start---
// @filename: config.ts
import { GatewayIntentBits } from 'discord.js';

export const config = {
    bot: {
        clientOptions: { intents: [GatewayIntentBits.Guilds] },
        interactions: { path: './handlers' },
        commands: { path: './commands' },
        events: { path: null }
    },
    subscribers: { path: null }
};

// @filename: plugins/Rolls.ts
import { Plugin } from '@seedcord/gateway';

export class Rolls extends Plugin {
    public async init(): Promise<void> {}

    public async countFor(userId: string): Promise<number> {
        return userId.length;
    }
}

// @filename: bot.ts
// ---cut-end---
import { Seedcord } from '@seedcord/gateway';
import { OAuth } from '@seedcord/plugin-oauth';

import { config } from './config';
import { Rolls } from './plugins/Rolls';

const Login = OAuth.with({
    onLogin: async ({ user }) => {
        const count = await seedcord.rolls.countFor(user.id);
        return new Response(`You rolled ${count} times.`);
    }
});

export const seedcord = new Seedcord(config)
    .attach('rolls', Rolls)
    .attach('oauth', Login);
```

`Rolls` is a plugin of your own with a `countFor()` method. `onLogin` reads `seedcord.rolls`, and TypeScript needs the type of `seedcord` to check that line. The type of `seedcord` includes `Login`, and the type of `Login` includes `onLogin`, so none of them can finish. TypeScript reports every name on that path. The error on `new Seedcord` follows from the others, and TypeScript stops reporting it once they're fixed.

Nothing is wrong when the bot runs. `onLogin` only runs when someone logs in, and `seedcord` exists by then. The problem is only in the types, and there are two ways to fix it.

### Write the option's return type

```ts twoslash title="src/bot.ts"
// ---cut-start---
// @filename: config.ts
import { GatewayIntentBits } from 'discord.js';

export const config = {
    bot: {
        clientOptions: { intents: [GatewayIntentBits.Guilds] },
        interactions: { path: './handlers' },
        commands: { path: './commands' },
        events: { path: null }
    },
    subscribers: { path: null }
};

// @filename: plugins/Rolls.ts
import { Plugin } from '@seedcord/gateway';

export class Rolls extends Plugin {
    public async init(): Promise<void> {}

    public async countFor(userId: string): Promise<number> {
        return userId.length;
    }
}

// @filename: bot.ts
import { Seedcord } from '@seedcord/gateway';
import { OAuth } from '@seedcord/plugin-oauth';

import { config } from './config';
import { Rolls } from './plugins/Rolls';
// ---cut-end---
const Login = OAuth.with({
    onLogin: async ({ user }): Promise<Response> => {
        const count = await seedcord.rolls.countFor(user.id);
        return new Response(`You rolled ${count} times.`);
    }
});

export const seedcord = new Seedcord(config)
    .attach('rolls', Rolls)
    .attach('oauth', Login);

export default seedcord;
```

With `Promise<Response>` written on `onLogin`, TypeScript has the type of `Login` without reading the function's body. It checks the body afterwards, and `seedcord` has its type by then.

### Build the bot in two statements

Some return types are long to write, like the one for `values` in [`LinkedRoles.with()`](/plugins/linked-roles#what-values-gets). For those, attach the plugin you read in a first statement, and read that bot inside the option.

```ts twoslash title="src/bot.ts"
// ---cut-start---
// @filename: config.ts
import { GatewayIntentBits } from 'discord.js';

export const config = {
    bot: {
        clientOptions: { intents: [GatewayIntentBits.Guilds] },
        interactions: { path: './handlers' },
        commands: { path: './commands' },
        events: { path: null }
    },
    subscribers: { path: null }
};

// @filename: plugins/Rolls.ts
import { Plugin } from '@seedcord/gateway';

export class Rolls extends Plugin {
    public async init(): Promise<void> {}

    public async countFor(userId: string): Promise<number> {
        return userId.length;
    }
}

// @filename: bot.ts
import { Seedcord } from '@seedcord/gateway';
import { OAuth } from '@seedcord/plugin-oauth';

import { config } from './config';
import { Rolls } from './plugins/Rolls';
// ---cut-end---
const withRolls = new Seedcord(config).attach('rolls', Rolls);

const Login = OAuth.with({
    onLogin: async ({ user }) => {
        const count = await withRolls.rolls.countFor(user.id);
        return new Response(`You rolled ${count} times.`);
    }
});

export const seedcord = withRolls.attach('oauth', Login);

export default seedcord;
```

The type of `withRolls` is finished before `Login` is created, so `withRolls.rolls` has its type by the time `onLogin` reads it. A handler never gets this error because the bot's type doesn't include your handlers.
