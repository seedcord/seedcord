You've attached the plugin, but `this.core.db` still fails to compile. The property is there when the bot runs, so only the types are missing. `attach` returns a bot typed with `db`, but a handler reads `this.core`. seedcord declares the type of `this.core` in its own package, which never imports your bot file.

Without codegen, you'd declare those types by hand in a `declare module` block and update it each time you rename a key. `seedcord codegen` writes that block for you into `src/seedcord-gen.ts`.

```ts twoslash title="src/handlers/History.ts"
// @errors: 2339
import { SlashHandler, SlashRoute } from '@seedcord/gateway';

@SlashRoute('history')
export class History extends SlashHandler<'history'> {
    public async execute(): Promise<void> {
        await this.reply(String(this.core.db));
    }
}
```

TypeScript reports "Property 'db' does not exist on type 'Core'" on `this.core.db`. Nothing is wrong with the handler itself.

## What codegen writes

Every key you attached becomes one row on [`Core`](ref:gateway/Core), sorted by key. A group takes one row for all the plugins inside it. The same file also holds your command and emoji registries, which this sample leaves out.

```ts title="src/seedcord-gen.ts" output
// Generated by `seedcord codegen`. Do not edit by hand.
// Run `seedcord codegen` after changing your commands, plugins, or emoji config.

import type Bot from './bot';
import type { AttachedPlugin } from '@seedcord/gateway';

type Fits<
    Plugin extends { codegen(): Promise<unknown> },
    Row extends Awaited<ReturnType<Plugin['codegen']>>
> = Row;

// prettier-ignore
declare module '@seedcord/gateway' {
    interface Core {
        db: AttachedPlugin<(typeof Bot)['db']>;
        i18n: AttachedPlugin<(typeof Bot)['i18n']>;
    }
    // SlashRegistry, the context menu registries, and EmojiMap follow
    interface PluginTypes {
        'seedcord-locales': Fits<(typeof Bot)['i18n'], { messages: { bye: true; greet: true } }>;
    }
    interface DispatchMemberValues {
        t: Awaited<ReturnType<(typeof Bot)['i18n']['dispatchMembers']['t']>>;
    }
}

export {};
```

`Bot` is the default export of the file that your `instance` config key points to. Each row reads its type from that bot, so `db` has the type `attach` returns, minus the members only seedcord calls, like [`init()`](ref:core/Plugin.init). [Calling it from a handler](/writing-plugins#calling-it-from-a-handler) lists all of them. This only works when the default export is the value `attach` returns. If you [export the bot without it](/plugins#no-plugin-types-in-your-handler), `this.core.db` has the type `any`. If you export the bot only as a named const, codegen stops with the code `CliInstanceInvalid` before it writes anything.

[`AttachedPlugin`](ref:core/AttachedPlugin) is the type that omits those members. It also omits the class's private members, so `this.core.db` isn't assignable to a parameter typed as the [`Mongoose`](ref:plugin-mongoose/Mongoose) class. To pass it to a function of your own, type that parameter as `AttachedPlugin<Mongoose>`.

[`PluginTypes`](ref:core/PluginTypes) holds the types that each plugin's [`codegen()`](ref:core/Plugin.codegen) returns from your project's files. Say a translations plugin attached as `i18n` writes the row above. It lists the message keys in your `locales` folder, so `this.core.i18n.t()` accepts `'bye'` or `'greet'` and rejects a typo. Each row is keyed by the plugin's `static id`, like `'seedcord-locales'`, and `Fits` checks it against the plugin at every key you attached it under. To add a row from your own plugin, read [Writing types from codegen](/writing-plugins/codegen).

[`DispatchMemberValues`](ref:types/DispatchMemberValues) gets one row for each key in a plugin's [`dispatchMembers`](/writing-plugins#adding-a-value-to-every-handler). The `t` row types `this.t` on every handler.

The `Core` block appears once you've attached something. `PluginTypes` appears once a plugin has written a row, and `DispatchMemberValues` appears once a plugin has `dispatchMembers`.

<Callout type="transport">

Each transport package declares its own `Core`, so the `declare module` line uses the package you import [`Seedcord`](ref:gateway/Seedcord) from. A gateway bot's file uses `declare module '@seedcord/gateway'`, and an http bot's uses `declare module '@seedcord/http'`.

</Callout>

## When to run it

The generated file only changes when codegen runs, so a stale one either misses a new key or still declares a key you removed.

- In `seedcord dev`, press `g` to run codegen after you add a file that a plugin reads during codegen, like a Mongoose service. Press `r` to restart the bot after you attach a plugin or rename its key, since dev rewrites the file when the bot starts.
- Outside dev, run `seedcord codegen`.
- In CI, `seedcord codegen --check` throws `CliCodegenOutOfDate` when the file is stale.

Once codegen has run, your editor offers `db` on `this.core`.

```ts twoslash
// @noErrors
import { SlashHandler, SlashRoute } from '@seedcord/gateway';
import type { AttachedPlugin } from '@seedcord/gateway';
import type { Mongoose } from '@seedcord/plugin-mongoose';

declare module '@seedcord/gateway' {
    interface Core {
        db: AttachedPlugin<Mongoose>;
    }
}

@SlashRoute('history')
export class History extends SlashHandler<'history'> {
    public async execute(): Promise<void> {
        // ---cut---
        this.core.
        //        ^|
        // ---cut-after---
    }
}
```
