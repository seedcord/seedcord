---
title: Typing a plugin
description: What codegen writes so this.core.db compiles.
---

You attached the plugin, but `this.core.db` still fails to compile. The property is there when the bot runs, so only the types are missing. `seedcord codegen` writes them into `src/seedcord-gen.d.ts`.

```ts twoslash title="src/handlers/History.ts"
// @errors: 2339
import { SlashHandler, SlashRoute } from '@seedcord/gateway';

// ---cut---
@SlashRoute('history')
export class History extends SlashHandler<'history'> {
    public async execute(): Promise<void> {
        await this.reply(String(this.core.db));
    }
}
```

## What codegen writes

Every key you attached becomes one row on `Core`, sorted by key.

```ts title="src/seedcord-gen.d.ts" output
// Generated by `seedcord codegen`. Do not edit by hand.
// Run `seedcord codegen` after changing your commands, plugins, or emoji config.

import type Bot from './bot';

// prettier-ignore
declare module '@seedcord/gateway' {
    interface Core {
        db: (typeof Bot)['db'];
    }
}

export {};
```

That `Bot` binding is the default export of the file your `instance` key names, which is how each row reads a key's type from the bot you actually built. Exporting that bot as a named const alone stops codegen before it writes anything, with the code `CliInstanceInvalid`.

The [`Core`](ref:gateway/Core) block only appears once you have attached something. Its `declare module` line names the package you import `Seedcord` from, so the same file on an http bot opens `declare module '@seedcord/http'`.

## When to run it

Run `seedcord codegen` after you attach a plugin, remove one, or rename a key.

`seedcord dev` regenerates the file too, whenever you answer `y` to its re-register prompt. That prompt only reads your command files, so a change to what you attach never raises it. This one stays yours to run.
