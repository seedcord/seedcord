---
title: Mongoose services
description: Write a service class for each MongoDB collection with the mongoose plugin, and read those services from any handler.
---

Without services, every handler that looks up a user would import the model and write its own `findOne` call. Changing how you look a user up would then mean finding every copy.

A service keeps a collection's queries in one class. Extend [`MongooseService`](ref:plugin-mongoose/MongooseService), declare the schema as a static, and decorate the class with a key. Handlers then call its methods through that key.

```ts twoslash title="src/services/Users.ts"
import {
    MongooseService,
    RegisterMongooseService
} from '@seedcord/plugin-mongoose';
import mongoose from 'mongoose';

import type { MongooseDocument } from '@seedcord/plugin-mongoose';

interface IUser extends MongooseDocument {
    username: string;
    streak: number;
}

@RegisterMongooseService('users')
export class Users extends MongooseService<IUser> {
    public static schema = new mongoose.Schema<IUser>({
        username: { type: String, required: true, unique: true },
        streak: { type: Number, default: 0 }
    });

    public findByName(username: string): Promise<IUser | null> {
        return this.model.findOne({ username }).lean().exec();
    }
}
```

- **`IUser`** lists the fields a user document has. It extends [`MongooseDocument`](ref:plugin-mongoose/MongooseDocument), which declares `_id: string`, the one field every document has.
- **[`@RegisterMongooseService('users')`](ref:plugin-mongoose/RegisterMongooseService)** gives the class its key. You read the service from the plugin's [`services`](ref:plugin-mongoose/Mongoose.services) under that key, like `this.core.db.services.users`. It's typed as `Users` once [codegen has run](#typing-the-services).
- **`MongooseService<IUser>`** is the base class. Passing `IUser` types `this.model` as `Model<IUser>`, so TypeScript checks the fields in every query on that model against `username` and `streak`. Without the type argument, the model's type only has `_id`.
- **`schema`** is the Mongoose schema the plugin builds the model from. Make sure it's `static` because the decorator fails to compile without it.
- **`findByName`** holds the lookup. You call that method from any handler, so the query is written once.

## You never construct a service

The plugin builds your services right after it connects. It imports every code file under the `path` you gave the [mongoose plugin](/plugins/mongoose), the way [`importFiles`](ref:utils/importFiles) does. For each exported class that extends `MongooseService` and has the decorator, it builds the model from `schema`, constructs the class, and adds the instance to the plugin's [`services`](ref:plugin-mongoose/Mongoose.services) map under its key.

If two classes use the same key, `init()` and `seedcord codegen` both throw `CoreDuplicateName` with both class names. The message from `init()` includes each class's file path.

<Callout type="warning">

If an exported class that extends `MongooseService` isn't decorated with `@RegisterMongooseService`, the plugin logs a warning with the class name and skips it. The plugin skips an unexported class without a warning. Either way `services.users` reads `undefined`. Codegen skips the class too, so once it has run, `services.users` fails to compile.

</Callout>

## The model name sets the collection

The plugin uses your key as the Mongoose model name. Mongoose pluralizes that name to pick the collection, so a key of `user` reads and writes the `users` collection. That's fine for a new database. If your collection already exists under a different name, pass `modelName` so the model name can differ from the key.

```ts twoslash
import {
    MongooseService,
    RegisterMongooseService
} from '@seedcord/plugin-mongoose';
import mongoose from 'mongoose';

import type { MongooseDocument } from '@seedcord/plugin-mongoose';

interface IUser extends MongooseDocument {
    username: string;
}

// ---cut---
@RegisterMongooseService('users', { modelName: 'app_user' })
export class Users extends MongooseService<IUser> {
    public static schema = new mongoose.Schema<IUser>({
        username: { type: String, required: true }
    });
}
```

With `modelName: 'app_user'`, mongoose reads the `app_users` collection, while you still read the class as `services.users`. `modelName` takes any non-empty string, so your editor doesn't suggest one and TypeScript can't catch a misspelled model name.

## Typing the services

The plugin finds your services by importing `path` when the bot starts, but TypeScript only reads your source. Without codegen, you'd write a `declare module` entry per service and update it each time you rename a key.

[`seedcord codegen`](/plugins/typing) imports `path` the same way and writes each key it finds into `src/seedcord-gen.ts`. After that, `services.users` is typed as your `Users` service, and the decorator offers the keys codegen found. With a `users` and a `guilds` service, it offers both:

```ts twoslash
// @noErrors
import { RegisterMongooseService } from '@seedcord/plugin-mongoose';

import type {} from '@seedcord/gateway';

declare class Users {}
declare class Guilds {}

declare module '@seedcord/gateway' {
    interface PluginTypes {
        '@seedcord/plugin-mongoose': {
            services: { users: typeof Users; guilds: typeof Guilds };
        };
    }
}

// ---cut---
RegisterMongooseService('
//                       ^|
```

Until codegen has run once, the decorator accepts any key, and TypeScript types every entry on `services` as `object`.

<Callout type="warning">

If you add or rename a service, its decorator fails to compile until codegen runs again because the generated file only lists the keys from the last run. Run `seedcord codegen` after each one.

</Callout>

## Reading a service

In a handler, you get a service from the plugin's `services` map, under the key you declared.

```ts twoslash hovers
import { SlashHandler, SlashRoute } from '@seedcord/gateway';
import {
    MongooseService,
    RegisterMongooseService
} from '@seedcord/plugin-mongoose';
import mongoose from 'mongoose';

import type {
    Mongoose,
    MongooseDocument
} from '@seedcord/plugin-mongoose';

interface IUser extends MongooseDocument {
    username: string;
}

@RegisterMongooseService('users')
class Users extends MongooseService<IUser> {
    public static schema = new mongoose.Schema<IUser>({
        username: { type: String, required: true }
    });

    public findByName(username: string): Promise<IUser | null> {
        return this.model.findOne({ username }).lean().exec();
    }
}

declare module '@seedcord/gateway' {
    interface Core {
        db: Mongoose;
    }
    interface PluginTypes {
        '@seedcord/plugin-mongoose': {
            services: { users: typeof Users };
        };
    }
}

@SlashRoute('history')
class History extends SlashHandler<'history'> {
    public async execute(): Promise<void> {
        // ---cut---
        const found =
            await this.core.db.services.users.findByName('ada');

        await this.reply(
            found ? `Found ${found.username}.` : 'No record.'
        );
        // ---cut-after---
    }
}
```

`findByName` resolves to an `IUser` or `null`, so you check `found` before you read `username`.

If you read `services` before the plugin's `init()` has finished or after `dispose()`, the read throws `PluginNotReady`. Your handlers never read it that early though, because they only start receiving interactions once `init()` has finished.
